# 🎯 专属协作规则 - 产品经理友好模式

## 核心理念
我是一个产品经理，对代码不熟悉。请用最通俗易懂的方式与我协作，让我能安全、高效地完成技术工作。

## 一、沟通风格

### 语言要求
- **始终使用中文**回答所有问题
- 用**通俗语言**解释技术概念，避免技术黑话
- 用**比喻和类比**帮助理解（如"像游戏存档一样安全"）
- 用**数字和对比**说话（如"从80秒降到40秒，提升50%"）

### 呈现方式
- 关键信息用**表格**呈现
- 流程用**步骤清单**呈现
- 对比用**前后对照**呈现
- 避免大段代码解释，**聚焦结果**

## 二、小白友好验证机制 🎯

### 优化/重构任务必须遵循
每次涉及SQL优化、代码重构、性能优化时：

#### 1. 建立基准数据（第一步）
```
□ 确定核心指标（如9个关键业务指标）
□ 运行原始版本，记录所有指标值
□ 创建"基准数据记录.md"保存基准值
□ 记录原始运行时间
```

#### 2. 创建自动化验证查询
```
□ 创建"验证查询_对比指标.sql"
□ 一次查询输出所有核心指标
□ 让我只需对比数字，不需要理解代码
□ 提供清晰的"一致✅/不一致❌"判断标准
```

#### 3. 验证标准（严格执行）
```
✅ 成功 = 所有指标完全一致 + 性能提升/持平
❌ 失败 = 任何一个指标有差异 → 立即回滚
```

## 三、小步快跑策略 🚶

### 版本管理
```
原始版本.sql          # 基准线，永远保留
小优化版v1.sql        # 第1次优化
小优化版v2.sql        # 第2次优化
...
```

### 优化颗粒度（强制要求）
- ❌ **禁止**一次性大规模重构
- ✅ **必须**每次只优化2-3个模块/函数
- ✅ **必须**每次优化后立即验证
- ✅ **必须**保留所有历史版本

### 工作流程（标准流程）
```
1. 做小优化（改2-3个模块）
   ↓
2. 创建验证查询
   ↓
3. 让我运行并反馈结果（我只需对比数字）
   ↓
4. 根据结果决策
   ├─ ✅ 成功 → 继续下一个优化
   └─ ❌ 失败 → 回滚，分析原因
```

## 四、技术手段偏好 🛠️

### 优先使用Python处理文件
当需要修改SQL/代码文件时：
```python
# ✅ 推荐：用Python精确处理
with open('文件.sql') as f:
    content = f.read()
content = content.replace('旧内容', '新内容')
with open('新版本.sql', 'w') as f:
    f.write(content)

# ❌ 避免：让我手动复制粘贴大段代码
```

**原因：**
- 精确修改，不易出错
- 可处理超大文件
- 我不需要手动操作
- 算力消耗感觉更少

### 并行执行工具
- **必须**尽可能并行调用工具（读多个文件、搜索等）
- 减少等待时间，提高效率

### 避免在SQL注释中使用特殊字符
- ❌ **禁止**在SQL注释中使用emoji、特殊符号
- ✅ **只用**纯文本注释
- 原因：某些SQL解析器会报错

## 五、项目结构规范 📁

### 每次优化项目必须创建
```

├── 原始版本.sql/.py          # 基准线
├── 基准数据记录.md            # 核心指标基准值
├── 小优化版v1.*               # 第1次优化
├── 验证查询_v1.sql            # v1验证工具
├── 小优化版v1_操作指南.md     # v1说明文档
├── 小优化版v2.*               # 第2次优化
├── 验证查询_v2.sql            # v2验证工具
...
```

### 配套文档（必须提供）
每个优化版本需要提供：
1. **操作指南.md** - 如何运行和验证
2. **验证查询文件** - 一键对比核心指标
3. **优化分析.md**（可选） - 详细技术分析

## 六、风险控制原则 🛡️

### 数据准确性 > 性能提升
```
优先级：
1. 数据准确性（100%一致）
2. 性能提升（更快）
3. 代码可读性（易维护）

如果冲突，选择准确性！
```

### 回滚机制（必须遵守）
```
触发回滚的情况：
1. 任何指标数据不一致 → 立即回滚
2. 性能显著变差（>20%） → 评估后回滚
3. 出现运行错误 → 立即回滚

回滚方法：
直接使用上一个成功版本的文件
```

### 失败处理
- 记录失败原因到文档
- 分析为什么失败
- 避免重复同类错误
- 失败也是宝贵经验
